# TEST-0002: Establish story patterns in test epic: pattern scaffolding and validation harness

> Establish story patterns in test epic: pattern scaffolding and validation harness

**Type:** default
**Epic:** [TEST](TEST)
**Status:** in_progress
**Blueprint:** [implementation-story-blueprint](implementation-story-blueprint)

## Goal

The test epic has an empty `pattern/` folder. Seed it with the first story pattern
blueprints and prove that story lifecycle commands and a second, parallel session can
consume them. This story is one of two deliberately parallel tasks (sibling: TEST-0003
in subepic test-sandbox, executed in a separate Claude session).

## Requirements

### R1: Epic-level story pattern blueprints

**Acceptance Criterion:** `test/_grid4d/pattern/` contains at least two pattern
documents following ahabase naming (`<scope>-<unique-name>.md`, scope = `test`),
e.g. `test-story-simulation-pattern.md` (how simulation stories are framed: purpose,
participants, defect capture protocol) and `test-parallel-session-protocol.md` (how
two parallel stories coordinate: disjoint file territory, shared-state watchpoints,
landing order).

### R2: Patterns are consumable, not decorative

**Acceptance Criterion:** Each pattern states at least one concrete, checkable rule
that a story execution can follow or violate; TEST-0002's own execution visibly
follows the patterns it introduces (self-application).

### R3: Parallel-session readiness evidence

**Acceptance Criterion:** The story document or notes record which shared state the
two sessions touch (active_story in `_data/evolucean/state.json`, git refs, counters
branch) and what was observed when both sessions ran, including any defect captured
into an issue or an Evolucean story.

## Acceptance Criteria

- [x] Two or more pattern documents exist in `test/_grid4d/pattern/` with ahabase-compliant names
- [x] Each pattern carries at least one checkable rule
- [ ] Parallel-session observations recorded (shared state, defects)

### Shared state watchpoints

Observations so far (2026-09-13, single session driving both stories until the
second session opens):

- **Epic resolution default** — `story create` without `--epic` minted into the
  primary epic (EVOLUCEAN-0281) even though cwd was the test epic; the ghost
  story was pruned. Guard proposed: warn when calling tree and resolved epic
  disagree.
- **Counters branch** — sequential minting (TEST-0002, then TEST-SANDBOX-0001)
  reserved both IDs atomically; no race observed yet (single writer).
- **active_story** — one global slot; switching stories required explicit
  `pause`/`resume`; the second session must `resume TEST-SANDBOX-0001` and the
  swap will be the first true two-writer observation.
- **Worktree layout** — flat `_worktrees/test-0003` violated the hierarchical
  convention mid-run and was `git worktree move`-d into
  `_worktrees/test/test-sandbox/TEST-SANDBOX-0001`.
- **Story file minting** — `story create` in the test epic minted the story
  `.md` but not a `-tests.md` template (both files were minted in the primary
  epic); tests file created manually here.
- **km_logger placement** — the knowledge map was created in the main tree
  (where the story was first read) and had to be moved into the story worktree;
  watch whether the hook keeps writing into the worktree now.
- **Stale bound tree after worktree move (defect)** — the hook kept writing the
  knowledge map into the main tree even after all work moved to the worktree.
  Root cause: the collaboration scope's `tree` was bound at story-create time
  (main tree) and the resume fast path (`Already active`, hooks.py) returns
  without rebinding, so `log_file_access` faithfully targeted the stale tree.
  Workaround applied: `pause` + `resume` from the worktree (fresh bind updates
  scope["tree"] via resolve_epic_root_from_cwd). Candidate occurrence for the
  Evolucean issue `km-logger-writes-wrong-tree`; related to
  `story-create-worktree-bootstrap-manual` (a worktree-aware create would bind
  the right tree from the start).
