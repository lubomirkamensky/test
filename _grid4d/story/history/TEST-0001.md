## Notes

Experiment log (2026-09-11):

1. **Story pattern cross-epic resolution** - works: this Epic declares
   `**StoryPattern:** story-pattern-default` but has an empty `pattern/`;
   `discovery.find_pattern` resolves name-only across the workspace to
   evolucean's `implementation/patterns/story-pattern-default.md`, and the
   pattern-based stop-handler status renders all 6 phases correctly.
2. **Jira-style story ID (SANDBOX-42)** - created manually (no `--id`
   option exists). Pause/resume/active-pointer/pattern all ID-agnostic and
   correct. Branch `feature/SANDBOX-42-*` fine. Hazard: `_build_version`
   maps the tracker number straight into the version minor
   (`0.0042.0.0000.00`) - collision risk with CLI story numbers in a
   long-lived repo. Filed as
   [jira-generated-story-ids](jira-generated-story-ids) (evolucean idea).
3. **Subepic story pattern (test-jira + story-pattern-autonomous)** -
   broken: identity `**StoryPattern:**` has no effect on minted subepic
   stories. All three resolution paths fail (R0 reads epic-level story/
   only; R1 first-segment prefix heuristic can never match TEST-JIRA- and
   skips the identity doc as story-ID-shaped; R2 registry has no
   story_prefixes). Filed as
   [subepic-story-pattern-resolution-broken](subepic-story-pattern-resolution-broken)
   (evolucean issue).
4. **Story types** - `--type docs` on this Epic is refused cleanly
   ("Unknown story type: docs. Available types: default"); but the
   `story create --help` text advertises docs/hotfix that are unavailable
   without a per-epic story_types block. `story create --subepic` mints a
   4-digit subepic ID (TEST-JIRA-0001) and activates the new story as a
   side effect.
